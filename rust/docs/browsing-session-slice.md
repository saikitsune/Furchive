# Opt-in remembered browsing controls

Preferences has Remember browsing controls, off by default. The Rust host captures only a successfully submitted Search/Favorites query+page or Pool ID/ratings+offset, including successful cross-page cursor position. It does not accept a renderer-supplied session-write snapshot, and never persists a selected media ID, opaque handle, URL, credential, authenticated identity, native root grant or running-download intent.

On restart the persisted non-authoritative DTO loads controls only. Open remembered page is an explicit new search/favorites/pool request using normal current account filters; it cannot restore old visibility, media, credentials or download-root authority. A bounded closed DTO validates query/rating/user/position and32KiB size. Existing settings without last_session remain readable; disabling and successfully saving atomically drops the intent, and Forget remembered browsing explicitly forgets it without clearing artwork or downloads. Query tags/favorites username themselves are local browsing history; this is not encrypted history or secure erasure. Cache clear leaves this separate opt-in history intact; use Forget or disable to remove it.

Capture tickets fence request ordering and successful preference changes/forget/account/cache boundaries. An old provider reply cannot recreate forgotten controls; failed atomic persistence leaves memory unchanged and surfaces an error rather than pretending the state was saved. UI startup hydration is fenced against newer edits/search/forget/account reset/unmount. Snapshotting restored Svelte state before bridge calls avoids passing reactive proxy objects into structured IPC/test boundaries. UI artist control preserves the complete submitted query instead of silently dropping remembered artist filtering.
